Pipeline End-to-End con Spark Declarative Pipelines

De datos crudos en un Volume a un modelo dimensional en Gold, orquestado con Jobs y desplegado con Databricks Asset Bundles. Este documento es tu guía oficial para el proyecto final del curso.

1 Resumen del Proyecto

El proyecto final integra todo lo aprendido en el curso: ingesta incremental, arquitectura medallion, calidad de datos, modelado dimensional, orquestación y despliegue como código.

Objetivo

Construir un pipeline de datos end-to-end que ingiera 4 entidades relacionadas de un dominio de ventas retail, las procese a través de las capas Bronze → Silver → Gold, modele la capa Gold como un esquema estrella, y exponga los resultados en un dashboard de Databricks. Todo el pipeline debe estar escrito con Spark Declarative Pipelines (Lakeflow Declarative Pipelines / ex Delta Live Tables), usando STREAM para la ingesta incremental, con reglas de expectations en Silver y Gold, orquestado mediante un Job y empaquetado en un Databricks Asset Bundle.

Checklist de requisitos obligatorios

  • Pipeline end-to-end desde Bronze hasta Gold
  • Dashboard en Databricks construido sobre la capa Gold
  • Modelo dimensional tipo estrella en Gold (hechos + dimensiones)
  • 4 entidades de datos relacionadas entre sí (2 en CSV, 2 en JSON)
  • 3 archivos (batches) por cada entidad, simulando llegada incremental de datos
  • Diccionario de datos por cada entidad
  • Pipeline Bronze→Gold implementado 100% con Spark Declarative Pipelines
  • Uso de STREAM sobre las fuentes en el Declarative Pipeline
  • Expectations (reglas de calidad) en Silver y en Gold
  • Orquestación del pipeline mediante un Job de Databricks
  • Proyecto empaquetado como Databricks Asset Bundle (DAB)
  • Datos crudos almacenados en un Volume con estructura /Volumes/<catalogo>/<esquema>/<volumen>/{nombre_proyecto}/{entidad}
  • Catálogo, esquema y tabla documentados para cada capa
  • Archivo de "setup" que permita crear el Volume, el catálogo y los esquemas del proyecto
  • Proyecto alojado en GitHub, con el enlace del repositorio incluido en la entrega
  • Presentación con evidencia del desarrollo: imagen del pipeline desplegado y funcionando, e imagen del dashboard

Flujo completo

1️⃣ Los archivos CSV/JSON de cada entidad se depositan en el Volume. 2️⃣ El Declarative Pipeline los lee incrementalmente con STREAM hacia Bronze, creando STREAMING TABLE. 3️⃣ Se transforman y validan hacia Silver aplicando expectations, también como STREAMING TABLE. 4️⃣ Se modelan hacia Gold como dimensiones y hechos usando MATERIALIZED VIEW, también con expectations. 5️⃣ Un Dashboard de Databricks consume directamente las tablas Gold. 6️⃣ Todo se orquesta con un Job y se despliega con un Asset Bundle.

6 Calidad de Datos con Expectations

Debes definir expectations tanto en Silver como en Gold para cada entidad. No se exige un ejemplo de código: aquí se indica de manera funcional qué debe validar cada regla. Usa al menos una regla por severidad a lo largo del proyecto: warn, drop y fail.

CSV clientes

  • El identificador customer_id no debe ser nulo (clave primaria de la entidad)
  • El campo email debe tener un formato de correo válido
  • El campo segmento debe pertenecer a una lista de valores permitidos (Retail, Premium)

CSV productos

  • El identificador product_id no debe ser nulo (clave primaria de la entidad)
  • El campo precio_unitario debe ser mayor a cero
  • El campo stock_actual no debe ser negativo

JSON pedidos

  • El identificador order_id no debe ser nulo (clave primaria de la entidad)
  • El campo estado_pedido debe pertenecer a una lista de valores permitidos (completado, en_proceso, cancelado)
  • El campo total_pedido no debe ser negativo

JSON detalle_pedidos

  • El identificador order_item_id no debe ser nulo (clave primaria de la entidad)
  • El campo cantidad debe ser mayor a cero
  • Las llaves foráneas order_id y product_id no deben ser nulas
En Silver las reglas deben enfocarse en la validez estructural y de formato de cada campo. En Gold las reglas deben enfocarse en la integridad del modelo dimensional: que las métricas de fact_ventas sean coherentes (por ejemplo, montos y cantidades no negativos) y que las llaves foráneas hacia las dimensiones estén siempre presentes.

7 Spark Declarative Pipelines con STREAM

Todo el flujo Bronze → Silver → Gold debe implementarse obligatoriamente con Spark Declarative Pipelines (motor de Lakeflow Declarative Pipelines). No se provee código de ejemplo en este documento; el diseño e implementación del pipeline queda a cargo del alumno.

Requisito obligatorio

  • El pipeline completo (Bronze, Silver y Gold) debe estar construido con Spark Declarative Pipelines
  • La ingesta desde el Volume hacia Bronze debe usar STREAM para procesamiento incremental
  • Los flujos entre capas que correspondan a tablas de streaming (Bronze y Silver) deben usar también STREAM

Tipo de tabla por capa

CapaTipo de tabla
BRONZESTREAMING TABLE (STREAM)
SILVERSTREAMING TABLE (STREAM)
GOLDMATERIALIZED VIEW
Las tablas creadas en Bronze y Silver deben ser de tipo STREAM (streaming tables), mientras que las tablas de la capa Gold (dimensiones y tabla de hechos del modelo estrella) deben crearse como MATERIALIZED VIEW.

8 Orquestación con Job y Databricks Asset Bundle

El Declarative Pipeline se dispara desde un Job, y todo el proyecto se empaqueta y despliega usando un Databricks Asset Bundle (DAB).

Estructura del Bundle

mi_proyecto_final/
├── databricks.yml
├── resources/
│   ├── pipeline.yml        # Definición del Declarative Pipeline
│   └── job.yml             # Job que orquesta el pipeline
├── src/
│   └── transformations/
│       ├── 01_bronze.py
│       ├── 02_silver.py
│       └── 03_gold.py
└── dashboard/
    └── dashboard_gold.lvdash.json

La carpeta dashboard/ debe contener el archivo del dashboard exportado en formato .lvdash.json, correspondiente al dashboard de Databricks construido sobre la capa Gold.
